🗒️ 설명
---

`public/rhythm_stages_001_015.json` 이 빌드 산출물에 그대로 포함되어 **실서버에서 누구나 다운로드할 수 있다.**

```
GET http://suh-project.synology.me:3010/rhythm_stages_001_015.json
→ 200, 25,244 bytes
```

이 파일에는 **15개 스테이지의 단어·음절 구성·키매핑·정답 배열이 전부** 들어 있다.

```json
{
  "gameTitle": "Hackathon Rhythm Game",
  "keyLayout": ["a","s","d","f","j","k","l",";"],
  "rules": { "totalStages": 15, ... },
  "stages": [ { "word": "...", "validSyllables": [...], "inputSyllables": [...], "keyMapping": [...] } ]
}
```

### 왜 남아 있나

초기 구현에서 프론트가 이 정적 파일을 `fetch`해 스테이지를 로드했다(#79 시절). 이후 #133에서 동적 단어 풀 + `POST /games/start` API로 전환되면서 **참조가 사라졌지만 파일만 남았다.**

#160에서 백엔드 시드용 사본을 `backend/src/data/`로 옮기며 발견했다.

### 확인 결과

| 확인 항목 | 결과 |
|---|---|
| `src/` 전체에서 `rhythm_stages` 참조 | 없음 |
| `public/` 정적 파일 `fetch` 호출 | 없음 |
| `index.html` · `vite.config.ts` 참조 | 없음 |
| `dist/`에 복사되는지 | **복사됨** (Vite가 `public/`을 그대로 배포) |
| 실서버 접근 | **200 OK** |

즉 **아무도 쓰지 않는데 배포만 되고 있다.**

🔄 재현 방법
---

1. 브라우저에서 `http://suh-project.synology.me:3010/rhythm_stages_001_015.json` 접근
2. 15스테이지 단어·정답 데이터가 그대로 내려온다
3. 게임을 플레이하지 않고도 모든 스테이지 구성을 알 수 있다

✅ 예상 동작
---

- 사용하지 않는 정적 파일이 배포에 포함되지 않아야 한다
- 게임 단어·정답 데이터가 정적 URL로 공개되지 않아야 한다
- 단어는 인증(HMAC)이 걸린 `POST /games/start`를 통해서만 제공되어야 한다

> 참고: 단어 자체가 최고 등급 기밀은 아니지만, 랭킹 경쟁이 있는 게임에서 전체 스테이지 구성이
> 미리 노출되면 공정성에 영향을 준다. 무엇보다 **쓰지도 않는 파일**이므로 남길 이유가 없다.

🛠️ 해결 방안
---

`public/rhythm_stages_001_015.json` 삭제.

- 백엔드 시드용 사본은 `backend/src/data/rhythm_stages_001_015.json`에 있으므로 **데이터 유실 없음** (#160)
- 프론트 참조가 없으므로 코드 변경 불필요
- 삭제 후 빌드 → `dist/`에 미포함 확인 → 배포 후 해당 URL이 404(또는 SPA fallback)인지 확인
