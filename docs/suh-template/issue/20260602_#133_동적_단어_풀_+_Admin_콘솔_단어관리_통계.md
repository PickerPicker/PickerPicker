📝 현재 문제점
---

- 단어 데이터가 `docs/rhythm_stages_001_015.json` 정적 파일 1개에 15개 단어로 하드코딩되어 있다.
- 반복 플레이 시 단어 패턴이 항상 동일하여 사용자가 단어를 외워서 기계적으로 입력할 수 있다 — 게임성 저하.
- 단어를 추가/수정하려면 코드 수정 + 재배포가 필요하다 — 운영 비효율.
- GameOver 화면이 세로로 길고 빈약하여 단어별 통계 시각화 공간이 비어 있다.
- 단어별 통계(난이도, 노출 횟수, 정확도)를 추적할 수단이 없다 — "내가 가장 어려워한 단어", "가장 많이 만난 단어" 분석 불가.

🛠️ 해결 방안 / 제안 기능
---

1. **단어 풀 동적 관리**: 단어 데이터를 DB로 이전하고, AI 생성 JSON을 admin이 화면에서 통째로 붙여넣어 등록·수정·삭제할 수 있는 콘솔을 제공한다.
2. **매 플레이 단어 추첨**: 게임 시작 시 백엔드가 단어를 추첨하여 stage 15개를 구성한다. `stage 1 = "커피"`(게임 이름 PickerPicker 연관)은 고정이며, stage 2~15는 난이도 그룹별 풀에서 무중복 무작위 추첨한다.
3. **단어별 통계**:
   - `word_stats` 테이블에 player × word 단위로 노출 횟수, 판정(perfect/good/miss) 카운트, 최고 점수를 UPSERT로 누적.
   - `session_word_results` 테이블에 세션별 stage별 raw 결과를 INSERT로 보존.
   - 본인 stats 화면에 "단어별 분석" 섹션 추가 — 많이 만난/어려운/잘하는 단어 TOP5.
   - admin 글로벌 통계 화면 추가 — 전체 유저 기준 노출 desc / 정확도 asc 등.
4. **다중 admin 계정**: env로 시드 1명 자동 생성 + admin 콘솔에서 추가 admin 등록 가능. 세션 토큰 방식(player 토큰과 격리, 24h TTL, 즉시 폐기 가능).
5. **GameOver 화면 개편**: 가로 2단 레이아웃 — 좌측 기존 점수/스테이지/콤보, 우측 이번 판 단어 카드 그리드(본인 정확도 + 전역 평균 비교).
6. **Practice 모드**: 동일하게 DB 풀에서 추첨하되 `/practice/start` 별도 엔드포인트로 분리하여 통계에 영향 없게 처리.

⚙️ 작업 내용
---

**백엔드**
- Alembic 도입(별도 이슈로도 등록) + 기존 5개 테이블 BigInt 통일 (`players`, `game_sessions`, `hall_of_fame`, `player_stats_daily`, `player_session`).
- 신규 테이블 5개 작성: `words`, `admins`, `admin_sessions`, `word_stats`, `session_word_results`.
- 신규 API: `POST /games/start`, `POST /practice/start`, `POST /admin/auth/login`, `POST /admin/auth/logout`, `POST /admin/admins`, `GET /admin/admins`, `GET/POST/PUT/DELETE /admin/words`, `GET /admin/stats/words`, `GET /admin/stats/overview`.
- 확장 API: `POST /players/result` (stage_results 누락 시 400, 단일 트랜잭션 내 raw INSERT + UPSERT), `GET /players/{nickname}/stats` (단어 분석 섹션 응답 확장).
- 단어 추첨 로직(`pick_stages`) — 고정 단어 우선 배치 + 난이도 그룹별 풀에서 무중복 랜덤.
- pydantic 검증 — 8개 키 모두 포함, 음절 집합 일치, input_length 일치 등.
- 자동 시드 — `words` 비어있으면 `rhythm_stages_001_015.json` 15개 INSERT (커피 = fixed_stage=1), `admins` 비어있고 env 존재 시 시드 1명 INSERT.
- HMAC + Bearer 이중 검증. `_PUBLIC_PATHS`에 `/admin/*` 추가 금지.

**프론트엔드**
- `src/components/admin/` 신규 디렉토리 — AdminLoginScreen, AdminDashboard, WordListPage, WordFormPage, WordStatsPage, AdminListPage, adminApi.
- `/admin/*` 라우트 추가 — admin_token 없으면 강제 리다이렉트.
- `GameScreen.tsx` — 정적 JSON fetch 제거, `POST /games/start` 호출, stage_results 누적·전송.
- `PracticeScreen.tsx` — `POST /practice/start` 사용, 통계 미반영.
- GameOverScreen 가로 2단 레이아웃 + 단어 카드 그리드.
- Stats 화면 단어 분석 섹션 추가.

3. FE PR-C: /admin 화면
4. FE+BE PR-D: 게임 흐름 전환 (`/stages` 제거, `/games/start` 사용)
5. FE PR-E: GameOver 개편 + Stats 단어 섹션
