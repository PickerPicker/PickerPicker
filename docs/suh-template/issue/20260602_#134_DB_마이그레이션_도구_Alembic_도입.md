📝 현재 문제점
---

- 현재 백엔드 DB 스키마 관리에 마이그레이션 도구가 없다 (`backend/` 하위에 `alembic/`, `migrations/`, `alembic.ini` 미존재).
- SQLAlchemy `Base.metadata.create_all()`에 의존하고 있으나, 이 방식은 기존 테이블의 컬럼 추가/타입 변경을 자동으로 처리하지 못한다.
- CLAUDE.md에도 "컬럼 추가 시 반드시 수동 ALTER 필요" 라고 명시되어 있음 — 운영 환경에서 매번 수동 `docker exec` + `psql` ALTER 실행 필요.
- 기존 테이블의 id 컬럼 타입이 혼재(`players.id = Integer`, `game_sessions.id = BigInteger`) — 통일 필요한데 마이그레이션 도구 없이는 안전한 변경 어려움.
- 다운그레이드/롤백 절차가 명문화돼 있지 않다.
- Spring 진영의 Flyway 같은 표준 마이그레이션 도구가 필요하다.

🛠️ 해결 방안 / 제안 기능
---

- **Alembic 도입** — SQLAlchemy 진영의 표준 마이그레이션 도구. Flyway와 개념 동일 (`alembic upgrade head` / `downgrade -1`, 자동 버전 추적 테이블 `alembic_version`).
- `backend/alembic.ini` + `backend/alembic/versions/` 디렉토리 구조 세팅.
- **baseline 마이그레이션** = 현재 운영 DB 스키마 캡처 (운영 DB에는 적용 안 함, `alembic stamp head`로 마킹).
- **두 번째 마이그레이션** = 기존 5개 테이블 id 컬럼 전부 `BigInteger` 통일 (`players`, `hall_of_fame`, `player_stats_daily`, `player_session` 변경. `game_sessions`는 이미 BigInteger). FK 컬럼도 동시 변경.
- Docker entrypoint에서 `alembic upgrade head` 자동 호출 (uvicorn 시작 전).
- 자동 시드(words/admins) 로직과 분리 — Alembic은 스키마만, 시드는 별도.
- `alembic revision --autogenerate` 활성화 — 모델 diff 자동 작성.

⚙️ 작업 내용
---

**백엔드**
- `uv pip install alembic` 추가 (`pyproject.toml` dependencies).
- `alembic init backend/alembic` 실행 후 `env.py`를 SQLAlchemy `Base.metadata` 참조하도록 수정.
- `alembic.ini`의 `sqlalchemy.url`을 환경변수 기반으로 변경 — `os.getenv("DATABASE_URL")` 사용.
- baseline revision 작성: `alembic revision -m "baseline"` + 빈 upgrade/downgrade (운영 DB는 `alembic stamp head`로 적용).
- BigInt 통일 revision 작성: 모든 id/FK 컬럼 `ALTER COLUMN ... TYPE BIGINT USING ...::BIGINT`.
- `Dockerfile` 또는 entrypoint 스크립트에 `alembic upgrade head` 추가.
- `backend/src/core/database.py`의 `create_all` 호출 제거 또는 Alembic 미적용 환경(테스트용)에서만 작동하도록 분기.

**테스트**
- `alembic upgrade head` → `downgrade base` → `upgrade head` 정상 동작.
- 운영 DB에서 baseline `stamp` 적용 후 BigInt 마이그레이션 정상 적용되는지 staging 검증.

**문서**
- README 또는 CLAUDE.md에 마이그레이션 운영 가이드 추가 ("새 revision 만들기", "운영 적용 절차").
