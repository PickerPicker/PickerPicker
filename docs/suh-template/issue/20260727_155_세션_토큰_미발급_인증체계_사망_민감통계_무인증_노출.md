🗒️ 설명

전체 코드 검수(v0.0.133) 결과, **세션 토큰이 단 한 번도 발급되지 않아 인증 체계 전체가 죽어 있다.**

`src/services/authService.ts`의 `login()`이 프론트 어디에서도 호출되지 않는다. `StartScreen`은 PIN 입력 후 `playerService.verifyPin()`만 호출하고 끝낸다. `POST /auth/login`을 부르는 코드가 없으므로 `sessionStorage`에는 토큰이 저장되지 않는다.

그 결과 아래가 전부 연쇄적으로 무력화됐다.

| 대상 | 상태 |
|---|---|
| `POST /auth/login`, `POST /auth/logout` | 호출자 없음 (dead endpoint) |
| `player_sessions` 테이블 | 항상 비어 있음 |
| `backend/src/core/security.py` (`require_player` / `optional_player` / `resolve_token`) | 어디에서도 import되지 않는 **전체 dead code** |
| `PATCH /hall-of-fame/motto` | Bearer 필수인데 토큰이 없어 **도달 불가** |
| `HallOfFameTab.tsx:28` 한마디 수정 버튼 | `getStoredToken()`이 항상 `null` → **아무에게도 보이지 않음** |

#143에서 "Bearer 토큰 발급 흐름이 없어 무조건 실패"하던 통계 공개 토글을 **토큰을 걷어내는 방향**으로 해결했고, 그 과정에서 명예의 전당 한마디 기능(#117)이 함께 죽었다.

🔄 재현 방법
---

**A. 남의 민감 통계 열람**

1. 아무 브라우저에서 개발자도구 콘솔을 연다
2. 임의 닉네임으로 `GET /players/{닉네임}/stats` 를 호출한다 (HMAC 헤더는 번들에서 그대로 얻을 수 있음)
3. 해당 유저의 `habit.by_hour`(몇 시에 게임하는지), `habit.session_gap_minutes`(플레이 간격), `words.hardest`(약점 단어)가 전부 응답에 담겨 돌아온다
4. 그 유저가 설정에서 **통계를 비공개로 돌려놨어도 동일하게 조회된다**

**B. 한마디 기능 도달 불가**

1. 1위를 달성해 `is_hall_of_famer = true` 상태가 된다
2. 명예의 전당 탭에 들어간다
3. 한마디 수정 버튼이 나타나지 않는다 (`getStoredToken()`이 항상 null이므로 조건 불성립)

**쓰기 엔드포인트도 무인증이다.**

| 엔드포인트 | 가능한 일 |
|---|---|
| `POST /players/result` | 임의 닉네임으로 임의 점수 저장 → 랭킹 조작. 없는 닉네임이면 `player_service.py:108`에서 계정까지 새로 생성 |
| `PATCH /players/{nickname}/stats-visibility` | 제3자가 남이 비공개로 돌린 통계를 공개로 되돌림 |
| `PATCH /players/{nickname}/tutorial-seen` | 동일 |

HMAC이 막아준다는 전제이지만 `VITE_SECRET_KEY`는 프론트 번들에 인라인되므로 누구나 서명을 만들 수 있다. 게다가 서명 대상이 `timestamp` 하나뿐이라(`authService.ts:5`, `main.py:140`) **서명 하나를 캡처하면 5분간 모든 경로·모든 body에 재사용**할 수 있다. #88에서 도입한 HMAC이 재전송·변조를 막지 못하는 상태다.

✅ 예상 동작
---

- PIN 로그인 성공 시 실제로 세션 토큰이 발급되어 `sessionStorage`에 저장되어야 한다
- `GET /players/{nickname}/stats` / `/sessions` 는 **본인만** 조회할 수 있어야 한다
- 통계를 비공개로 설정한 유저의 민감 정보는 어떤 경로로도 제3자에게 노출되지 않아야 한다
- `POST /players/result` 는 인증된 본인 명의로만 점수를 저장할 수 있어야 하고, 미등록 닉네임으로 계정이 생성되면 안 된다
- 1위 경험자에게 명예의 전당 한마디 수정 버튼이 정상 노출되어야 한다
- HMAC 서명은 요청 본문·경로·메서드까지 포함해 재사용을 막아야 한다

🛠️ 해결 방안
---

1. **토큰 발급 흐름 복원** — `StartScreen`의 PIN 검증을 `playerService.verifyPin()` → `authService.login()` 호출로 교체해 토큰을 실제 발급받는다
2. **읽기 보호** — 이미 존재하는 `security.py`의 `require_player`를 `/players/{nickname}/stats`, `/players/{nickname}/sessions`에 적용하고, 경로의 nickname과 토큰의 nickname이 일치하는지 검증한다 (불일치 시 403)
3. **쓰기 보호** — `stats-visibility`, `tutorial-seen`, `POST /players/result`에 동일하게 적용
4. **유령 계정 차단** — `save_game_result`에서 미등록 닉네임 자동 생성 로직을 제거하고 404를 반환한다
5. **HMAC 강화** — 서명 대상을 `timestamp + method + path + body(sha256)` 로 확장하고 FE/BE 양쪽을 함께 수정한다
6. **motto 부활** — 토큰 발급이 복원되면 `HallOfFameTab` 조건이 정상 동작하는지 확인한다
7. **문서 정합성** — `CLAUDE.md`의 API 표를 실제 코드와 일치시키고 누락된 `/hall-of-fame`, `/games/start`, `/practice/start`, `/admin/*` 를 추가한다
