📝 현재 문제점
---

실서버 DB의 플레이 기록이 2026년 5월 15일부터 시작합니다. 이 시기는 이전 대회 기간과 겹쳐, 심사 과정에서 기록 날짜만으로 기출품 이력이 드러납니다.

현재 데이터 분포:

| 테이블 | 행 수 | 기간 |
|--------|-------|------|
| players | 56 | 2026-05-15 ~ 2026-07-04 |
| player_stats_daily | 47 | 2026-05-16 ~ 2026-08-13 |
| hall_of_fame | 2 | 2026-05-18 ~ 2026-05-19 |
| word_stats | 24 | 2026-06-09 ~ 2026-08-13 |
| game_sessions | 1 | 2026-08-13 |
| session_word_results | 6 | 2026-08-13 |
| words / admins | 15 / 1 | 2026-06-05 |

날짜가 직접 화면에 보이는 곳은 **명예의 전당**입니다. 역대 챔피언 목록에 퇴위 날짜가 `05.19` 형태로 찍히고, 현재 챔피언 재위 기간도 시작일 기준으로 계산됩니다.

🛠️ 해결 방안 / 제안 기능
---

DB 전체 타임스탬프를 8월 구간으로 재정렬합니다. 단순히 일정 기간을 더하는 방식은 최신 데이터가 미래 날짜가 되어버리므로 쓸 수 없습니다.

**순번 기반 날짜 매핑**을 사용합니다.

- DB에 존재하는 서로 다른 날짜 17개를 시간순으로 정렬한 뒤, 8월 1일부터 13일까지에 순서대로 대응시킵니다.
- 시분초는 원본을 그대로 유지합니다. 시간대별 플레이 습관 분석(시간 히트맵)이 왜곡되지 않습니다.
- 매핑이 단조 증가하므로 모든 선후 관계가 보존됩니다. 가입일이 첫 플레이보다 뒤로 가거나, 챔피언 퇴위가 즉위보다 앞서는 일이 발생하지 않습니다.

⚙️ 작업 내용
---

- 대상 테이블: `players`, `player_stats_daily`, `hall_of_fame`, `word_stats`, `game_sessions`, `session_word_results`, `words`, `admins`, `admin_sessions`
- `player_stats_daily`는 (닉네임, 날짜) 복합 기본키라 날짜 압축 시 충돌 위험이 있습니다. 같은 사람이 가진 날짜끼리는 반드시 서로 다른 날짜로 가도록 매핑을 설계합니다.
- `admin_sessions`의 만료 시각은 매핑하지 않고, 새 생성 시각에 원래 유효기간을 더해 다시 계산합니다.
- 단일 트랜잭션으로 실행하고, 완료 후 검증 쿼리로 선후 관계와 날짜 범위를 확인합니다.
- 작업 전 전체 DB 백업을 확보합니다.

> 되돌릴 때는 백업본을 복원합니다. 한 달 뒤 원복 예정입니다.
