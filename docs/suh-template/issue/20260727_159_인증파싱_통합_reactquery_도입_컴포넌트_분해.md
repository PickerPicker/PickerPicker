🗒️ 설명
---

전체 검수에서 드러난 구조·품질 문제를 모아 정리한다. 기능 동작에 당장 문제를 일으키지는 않지만, 앞으로의 변경을 계속 비싸게 만드는 항목들이다.

**1. Bearer 파싱 로직 4벌 중복**

| 위치 | 상태 |
|---|---|
| `backend/src/core/security.py` | `require_player`/`optional_player` — 어디서도 쓰이지 않는 dead code |
| `backend/src/apis/auth_router.py` `logout()` | 인라인 `authorization.split()` |
| `backend/src/apis/hall_of_fame_router.py` `update_motto()` | 인라인 파싱 + `auth_service.verify_token` |
| `backend/src/dependencies/admin_auth.py` | admin 전용 별도 구현 |

같은 일을 하는 코드가 네 군데 흩어져 있고, 그중 정식 구현(`security.py`)이 아무도 쓰지 않는 쪽이다. 토큰 검증 함수도 `security.resolve_token`과 `auth_service.verify_token` 두 벌이다.

**2. react-query가 껍데기**

`@tanstack/react-query`를 설치하고 `main.tsx`에 Provider까지 넣었지만 `useQuery` 사용처가 **0건**이다. `lib/queryClient.ts` 주석에 "실제 마이그레이션은 별도 이슈에서 진행한다"고 명시되어 있다. 현재 모든 데이터 페칭은 `useState` + `useEffect` 수동 처리라, 화면 전환마다 중복 요청이 발생하고 로딩·에러 상태를 컴포넌트마다 따로 관리한다.

**3. 대형 컴포넌트**

| 파일 | 줄 수 | 담당 |
|---|---|---|
| `features/game/GameScreen.tsx` | 842 | 게임 루프 + 판정 + 결과 저장 + 게임오버 UI + 랭킹 조회 + 모토 수정 |
| `features/player/StartScreen.tsx` | 728 | 닉네임 입력 + PIN 로그인/생성/확인 + 설정 + 홈 UI |

한 파일이 너무 많은 책임을 갖고 있어 변경 시 영향 범위 파악이 어렵다.

**4. eslint-disable 22곳**

#151에서 react-hooks 규칙 위반 19건을 정리했지만, 상당수가 실제 수정이 아니라 `eslint-disable` 주석으로 억제됐다. 게임 타이밍 로직이라 조심스러운 건 이해되나, 억제된 채로 남으면 진짜 문제를 놓치게 된다.

**5. 기타**

- `datetime.utcnow()` 다수 사용 — Python 3.12+에서 deprecated. naive/aware 혼동 위험도 있다
- `player_service.py:191` — `player._is_new_champion = is_new_champion` 처럼 ORM 인스턴스에 임시 속성을 부착해 라우터로 전달한다. 타입 체커가 잡아주지 못한다
- `pages/HomePage.tsx` — 렌더 중 `window.innerWidth`를 직접 참조해 리사이즈에 대응하지 못하고, `SS_WELCOME_KEY` 상수가 컴포넌트 본문 안에 선언되어 매 렌더 재생성된다
- `store/playerStore.ts:68` — `toggleStatsPublic`이 스토어 안에서 직접 네트워크를 호출한다. 상태 저장소가 통신 책임까지 겸하고 있어 테스트와 재사용이 어렵다

✅ 예상 동작
---

- 인증 파싱은 한 곳에만 존재하고 나머지는 이를 재사용해야 한다
- 설치된 의존성은 실제로 쓰이거나, 쓰지 않을 거면 제거되어야 한다
- 한 파일이 하나의 책임을 갖고, 무엇을 하는지 내부를 읽지 않고도 알 수 있어야 한다
- 린트 억제 주석은 정말 불가피한 경우에만 남아야 한다

🛠️ 해결 방안
---

1. **인증 파싱 통합** — `core/security.py`를 단일 진실 소스로 삼고, `auth_router.logout`과 `hall_of_fame_router.update_motto`를 `Depends(require_player)` / `Depends(optional_player)`로 교체한다. `auth_service.verify_token`과 `security.resolve_token` 중복도 하나로 합친다. admin은 권한 체계가 달라 분리 유지한다
2. **react-query 실제 도입** — 랭킹·명예의전당·통계처럼 순수 조회 화면부터 `useQuery`로 옮긴다. 게임 루프처럼 실시간성이 중요한 부분은 건드리지 않는다. 도입 범위를 넘어서면 남는 부분은 후속 이슈로 넘긴다
3. **컴포넌트 분해** — `GameScreen`에서 게임 루프/판정을 커스텀 훅(`useGameLoop` 등)으로, 게임오버 화면을 별도 컴포넌트로 분리한다. `StartScreen`은 PIN 플로우를 분리한다. **게임 타이밍·판정 로직의 동작은 바꾸지 않는다**
4. **eslint-disable 해소** — 22곳을 하나씩 검토해 실제 수정이 가능한 것은 고치고, 불가피한 것만 사유 주석과 함께 남긴다
5. **`utcnow` 교체** — `datetime.now(UTC)` 로 일괄 교체하고 DB 컬럼의 timezone 처리와 일관성을 맞춘다
6. **반환 타입 정리** — `save_game_result`가 임시 속성 대신 `(Player, is_new_champion)` 튜플이나 전용 결과 객체를 반환하도록 바꾼다
7. **HomePage 정리** — `window.innerWidth`를 리사이즈 대응 훅으로 빼고, 상수를 모듈 스코프로 올린다
8. **playerStore 정리** — `toggleStatsPublic`의 네트워크 호출을 컴포넌트나 서비스 레이어로 옮기고 스토어는 상태만 관리하게 한다

> 검증: 각 단계마다 `npm run build`(tsc 포함) + `npm run lint` + 백엔드 `pytest`를 돌린다. 게임 플레이는 수동으로 판정 동작이 동일한지 확인한다.
